## 2. Принцип визуализации

**КАРТА УРОВНЯ, НЕ УЧЕБНИК**

Каждая иллюстрация — элемент игрового мира:
- **Инвентарь / слоты** — для структур данных, строк, списков
- **Skill Tree** — для прогрессии навыков и итогов дня
- **Арена** — для сравнения решений (до/после, метод A vs метод B)
- **Квестовая цепочка** — для пайплайнов и пошаговых процессов
- **Ловушки / боссы** — для типичных ошибок и подводных камней
- **Крафт-рецепт** — для сборки из частей (f-строки, join, форматирование)

## 5. Обязательные требования к содержимому

### Игровая эстетика
Каждая иллюстрация должна выглядеть как элемент игрового интерфейса — не учебник, не презентация:
- Данные показаны через **игровые метафоры**: инвентарные слоты, HP-бары, skill tree, арены, крафт-рецепты
- Элементы имеют **RPG-атрибуты**: рамки как UI панели, иконки как игровые символы, связи как световые нити
- Атмосфера **Hollow Knight**: тёмные пещеры, биолюминесценция, созерцательность — не агрессивный киберпанк

### Конкретные данные
Никаких абстракций типа «данные», «значение», «элемент»:
- Использовать реальные примеры из урока: `"Dragonborn"`, `nickname[5]`, `"меч, щит, зелье"`
- Числа конкретные: индексы `0..9`, результаты `→ "n"`, длина `len() = 10`
- Код в иллюстрации должен совпадать с кодом в тексте урока

### Весь текст на русском
- Заголовки, подзаголовки, подписи — строго кириллица
- Названия методов и код — латиница (это код, не текст)
- Примеры строк — на русском где возможно: `"Привет, {name}!"`, `"меч, щит"`
